# Internationalization

The app speaks Hungarian, English, Spanish, Portuguese, German, Italian and Chinese. Hungarian is the
**source language**: every string is written there first, and every other language is a translation of it.
English is also the **pivot**: it is the second source for any further language, because a sentence with
Hungarian suffixes and word order is a poor base for a direct translation.

## Where the text lives

```
crates/ride-i18n/languages.tsv        the registry: one row per language
crates/ride-i18n/locales/hu.json      the source catalog
crates/ride-i18n/locales/en.json      one finished translation (the pivot)
crates/ride-i18n/locales/es.json      one finished translation
crates/ride-i18n/locales/pt.json      one finished translation
crates/ride-i18n/locales/de.json      one finished translation
crates/ride-i18n/locales/it.json      one finished translation
crates/ride-i18n/locales/zh.json      one finished translation (Simplified Chinese)
crates/ride-i18n/GLOSSARY.tsv         the term glossary, a column per language
crates/ride-i18n/STYLE.tsv            the style rules, a column per language
crates/ride-i18n/locales/_meta.json   translator context, generated (not committed)
crates/ride-model/assets/workouts.json        the workout library, Hungarian source
crates/ride-model/assets/workouts.en.json     generated from workouts.en.map.json
crates/ride-model/assets/workouts.en.map.json flat { "hungarian": "english" } map
crates/ride-model/assets/workouts.es.json     generated from workouts.es.map.json
crates/ride-model/assets/workouts.es.map.json flat { "hungarian": "spanish" } map
crates/ride-model/assets/workouts.pt.json     generated from workouts.pt.map.json
crates/ride-model/assets/workouts.pt.map.json flat { "hungarian": "portuguese" } map
crates/ride-model/assets/workouts.de.json     generated from workouts.de.map.json
crates/ride-model/assets/workouts.de.map.json flat { "hungarian": "german" } map
crates/ride-model/assets/workouts.zh.json     generated from workouts.zh.map.json
crates/ride-model/assets/workouts.zh.map.json flat { "hungarian": "chinese" } map
```

`build.rs` embeds every `locales/*.json` (files starting with `_` are skipped) and computes
`COMPLETE_LOCALES` by comparing each catalog with the source key set. A language whose catalog is
missing keys is **not offered** in the settings dialog, and `detect()` falls back to Hungarian
instead of English: a rider whose language is unfinished sees a finished UI, never a half-translated
one. Translators still reach an unfinished catalog with `RIDE_LANG=es`.

## Using it from Rust

```rust
use ride_i18n::{t, tf, tn};

t("ui_hud.kezdes")                                  // "Kezdés" / "Inicio"
tf("route.bikerouter.name_with_km", &[("name", &name), ("km", &km)])
tn("ui_hud.rides_count", n, &[("n", &n.to_string())])  // picks .one / .other by the language rule
```

* `t` returns a `&'static str` (that is the signature the label helpers already had).
* `tf` substitutes `{name}` placeholders; an unknown placeholder is left as it is.
* `tn` appends `.one` / `.other` according to `PluralRule` (`other-only` for Hungarian and
  Chinese-like languages, `one-other` for English and Spanish).
* Numbers go through `ride_i18n::decimal` / `decimal_trimmed` so the decimal separator follows the
  language (Hungarian and Spanish use `,`, English uses `.`).
* The language is process-wide (`init`, `set_lang`); tests override it per thread with
  `with_lang`, so every existing Hungarian assertion keeps working.

A missing key falls back to the source text and, in a debug build, prints a line to stderr.

## The registry

`languages.tsv` is tab separated, one row per language, `#` starts a comment:

| column | meaning |
|---|---|
| `code` | BCP 47 primary tag, also the catalog's file name (`es` → `locales/es.json`) |
| `self_name` | the language's own name, shown in the picker and never translated (`Español`) |
| `html_lang` | the value of `<html lang>` |
| `plural_rule` | `other-only` or `one-other` |
| `decimal` | the decimal separator of everyday numbers |
| `script` | `latin`, `latin-ext`, `cyrillic`, … (a script Barlow does not cover falls back to a system font) |
| `rtl` | `yes` / `no` |

Adding a language is a row plus a catalog file; no Rust source changes.

## Extracting and checking

```powershell
node scripts/i18n/extract.mjs           # report: new literals, stale keys, format! templates
node scripts/i18n/extract.mjs --apply   # rewrite the Rust sources to t()/tf() and update hu.json

# a UI catalog: author the chunks, then merge them (coverage report, no half-written file)
node scripts/i18n/catalog_worklist.mjs zh        # target/c-zh/partNN.src.json, grouped by screen
node scripts/i18n/merge_catalog.mjs zh --check   # coverage of locales/zh.json
node scripts/i18n/merge_catalog.mjs zh           # write locales/zh.json

# the workout library: worklist, translation chunks, map, generated library
node scripts/i18n/workout_worklist.mjs en        # target/w-en/chunkNN.txt (only the new strings)
node scripts/i18n/merge_workouts.mjs en          # target/w-en/chunkNN.en.json -> workouts.en.map.json
node scripts/i18n/workouts.mjs en --check        # coverage of the workout library
node scripts/i18n/workouts.mjs en                # write assets/workouts.en.json

# the rendered UI: dump the text of every screen in the target language and scan it
node scripts/readme_shots.mjs --lang en --text --out target/en-text
node scripts/i18n/check_ui.mjs target/en-text
```

A UI catalog is authored the same way as the workout map: the headline text is split into chunks
(`target/c-<code>/partNN.json`, a flat `{ "key": "text" }` object each), and `merge_catalog.mjs`
unions them, refuses a key translated twice differently, names the source keys still missing, and
writes nothing while one is missing. A missing key is also the only thing `COMPLETE_LOCALES` cares
about, so this is what decides whether the picker offers the language.

`check_ui.mjs` looks for text that is still Hungarian in a *rendered* page: the letters `ő`/`ű` (which
neither English, Spanish, German nor Portuguese has) and a list of Hungarian words that carry no accent
(`Ki`, `hátra`, `kész`), which the accented heuristic of `extract.mjs` cannot see. Text that comes from the data — a
route name from the GPX, a font name — is reported as `data` and does not fail the run. This is how
the last hard-coded labels were found (the ghost selector's `Ki`, the `besorolatlan` category,
`1. kat.`, the `duration_label` "5 mp"/"20 perc"), after the extractor had declared the source clean. It
needs a rendered window, so it cannot run in a shell without an interactive desktop.
`readme_shots.mjs --lang <code>` resolves the labels it clicks from the catalog itself, so the same
scenario drives every language.

A translation may be longer than the source. `node scripts/i18n/overflow.mjs --lang <code>` opens the
app in a throw-away data directory, walks the ride screen, every top-bar dialog and the phone tabs, and
reports every visible element whose `scrollWidth` is larger than its `clientWidth`. Elements that
scroll on purpose are skipped; a clipped label or a spilling child is reported. Run it at
`--window 412x860` and at `1440x900`, and compare the run with the source language: an element that
already clipped in Hungarian is not a translation regression, a new one is.

`extract.mjs` scans Rust string literals that contain Hungarian characters plus a curated list of
unaccented ones (`EXTRA`), generates keys as `<crate>.<module>.<slug>` and dedupes identical text
globally, so the same sentence is translated once. It refuses to touch `format!` templates and
`#[error]` attributes; those are converted by hand to `tf`/manual `Display`, because a thiserror
attribute cannot call a function. It skips `examples/`, `tests/` and the Cargo `build.rs` at a crate
root, but *not* `src/build.rs`, which is an ordinary module with rider-facing error messages.

The workout library is translated through a flat map: the same step name appears in hundreds of
workouts and is translated once. `workouts.mjs` writes nothing while a string is missing — a
half-translated library would show two languages inside one workout. A translation is authored in
chunks under `target/w-<code>/` (an ordered JSON array per chunk, zipped with the matching list of
source strings), and `merge_workouts.mjs` turns the chunks into `assets/workouts.<code>.map.json`.

## Quality gates

`crates/ride-i18n/tests/catalogs.rs` fails the build when:

* a language in `languages.tsv` has no catalog file,
* a value is empty,
* placeholders differ from the source (`{}`, `{name}`, `{:.0}` …),
* a string lost or gained a leading/trailing space (several are glued to a link),
* a translation is still identical to the Hungarian (a short allowlist covers proper nouns and pure
  placeholder templates),
* a translation carries the letters `ő`/`ű` (English, Spanish, German, Portuguese and Chinese do not
  use them),
* Spanish calls the rider `lovas`/`jinete` instead of `ciclista`, English says `horseback`,
  `equestrian`, `jockey` or `horseman`, German uses `Reiter`/`Pferd`, Portuguese uses
  `cavaleiro`/`equitação`, or Chinese uses `骑马`/`马术`/`赛马` — a rider is on a bike,
* a Portuguese value uses a Brazilian form (`você`, `arquivo`, `salvar`, `excluir`, `tela`,
  `configuração`, `registro`, `celular`, `planejar`): the catalog is European Portuguese,
* a Chinese value uses the formal `您` (the UI addresses the rider as `你`) or a traditional Chinese
  character where the catalog is Simplified Chinese.

The `t()` calls themselves are covered by the UI tests: they render the dialogs and assert on the
Hungarian text, which is why the tests run with the source language unless they opt in.

### German: open questions for a native review

* `Workout` is used for `edzés`, the word of the library and of the English pivot, not `Training`;
  switching to `Training` would rename a heading, so it is a catalog-wide decision.
* `Fahrt` carries both `tekerés` (riding) and `menet`/`túra` (a stored ride). `Ausfahrt` would be
  more idiomatic for the latter, but the same word means "exit" on a route screen.
* `Leistung` is the watt metric in the tables and "performance" in prose; only the metric reading
  uses this word.
* `Tempo` (not `Geschwindigkeit`) is the speed tile, so its label keeps the width of the other
  languages; the widest remaining labels are the compounds (`Trittfrequenz`, `Schwellenleistung`).
* The 412 px and 1440 px layout runs found no clipped text, but a native pass over the long
  sentences is still open, and no native speaker has read the catalog (also stated in `CLAUDE.md`).

own language, not in the Hungarian order.

## What is not localized

* Saved names — a route saved as `Demó útvonal`, an imported workout, `Útpont 3` — are fixed when
  they are created and do not follow a language change (`docs/DECISIONS.md`).
* The bundled packaging metadata: `Dioxus.toml` (`short_description`, the permission
  descriptions) is single-language — `dx` has no per-language field, so the translations live there as
  comments — and the Android manifest's `@string/app_name` is the product name (the brand, not
  translated). The Linux desktop entry carries `Comment` in every supported language; the macOS
  `InfoPlist.strings` carries the localized Bluetooth prompt (`packaging/macos/<code>.lproj/`, e.g.
  `de.lproj/`).
* The numbers of the HUD stay column-aligned with a decimal point in every language; only running
  text uses the language's decimal separator.
