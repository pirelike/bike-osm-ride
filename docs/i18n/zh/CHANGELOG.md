# 变更日志

> **翻译说明。** 本文档的权威版本是匈牙利语 [`CHANGELOG.md`](../../../CHANGELOG.md)。本文件只是它的简体中文
> 译本，不是第二个事实来源；两者若有出入，以匈牙利语原文为准。

每个重要变更都按版本列出，遵循 [Keep a Changelog](https://keepachangelog.com/hu/1.1.0/) 的精神，项目遵循
[语义化版本](https://semver.org/lang/hu/)（仍是 0.x：界面和文件格式可能变化，但设置、路线和骑行文件保持
向后兼容）。内容来自提交信息；日期是提交的日期。

**v0.2.0** 和 **v0.2.2** 标签存在于仓库里，但没有对应的发行版：它们的发行运行失败了，内容出现在下一个
版本里（分别为 0.2.1 和 0.2.3）。已经推出去的标签不会移动；修复意味着一个新的 patch 版本。

### 修复
- **前瞻的海拔剖面：曲线会瞬间消失一下，圆点则跳到左边缘。** 窗口检查的是“起点 + 长度 − 起点”是否短于
  长度，而由于浮点舍入，这个条件在约三分之一的距离上就成立了：这时应用以为窗口已经撞到路线末尾，于是
  跳到那里一帧（例如位置在 2.4 km，尺子却显示 9.5–12 km）。现在它把窗口的末端与路线长度作比较；有一个
  测试在非整数的米制距离上全程扫过，守住这一点。
- **有些标签漏了翻译。** 留在目录之外的文本（幽灵选择器的“谁”按钮、“未分类”的爬坡类别、“2 类”这样的
  标记、路线加载的错误信息、给屏幕阅读器的描述、Street View 下载的状态行和错误信息）现在都来自目录，
  所以选西班牙语时它们也显示为西班牙语。`scripts/i18n/check_ui.mjs` 检查的是渲染后的界面，是它抓到
  这些的。
- **“自动”语言的说明过时了**：它写着遇到未知语言时以英语启动，而程序实际上以匈牙利语启动（别让人看到
  半成品目录）。文本现在写的是事实。
- **Android：“保存为 TCX” 没有留下可用的文件。** 文件试图直接写进“下载”文件夹，Android 11+ 不允许
  这样做，于是它落到了应用自己的、外部看不到的文件夹里，而提示却是“已保存”。现在会打开系统的“另存为”
  对话框（和备份时一样），由你选择位置。
- **设备窗口：连接真实设备时，模拟骑手也显示“连接中…”。** 模拟骑手会提供所有角色，而那一行只按角色
  判断是否正在连接。现在设备名称也算数。
- **Android：更长的连接超时**（30 秒，原来是 12 秒；服务发现 12 秒，原来是 6 秒）：Android 自己的直连
  也会在约 30 秒后放弃，而且 btleplug 自己还会重试。
- **Android：搜索没有报错却什么也找不到。** 清单里的 `BLUETOOTH_SCAN` 权限没有 `neverForLocation`
  标记，这种情况下 Android 12+ 在缺少位置权限时会静默地给出空的搜索结果。现在这个标记在，旧版
  （到 Android 11）的 `BLUETOOTH` / `BLUETOOTH_ADMIN` 权限也在。如果一次成功启动的搜索 30 秒内一个
  设备都没看到，应用会提示一次该检查什么（蓝牙、“附近的设备”权限，Android 11 及以下还有定位）。
- **Android：“无法打开 BLE 日志：Permission denied (os error 13)”。** 应用数据文件夹此前只从
  `/data/data/<包名>/files` 这个路径推断，而在次要用户、工作资料、Secure Folder 或“双开应用”下，
  那不是我们自己的文件夹。现在 Activity 的 `getFilesDir()` 返回值是首选，推断出来的路径
  （`/data/user/<n>/…`、`/data/data/…`）只是备用，而且每个前面都有一次写入试探。错误信息里也会写出
  文件路径。
- **Android：“蓝牙不可用：failed to resolve java class … Adapter class not found”。** 有两个原因。
  btleplug 的 Java 端没有被放进 APK：打包脚本（`packaging/android/resoverlay.sh`）现在会把所用
  btleplug 版本的 Java 源码复制进 Gradle 工程，并补一条 R8 规则，让发行构建不会把那些类裁掉。只做这
  一步还不够（手机上还是同一个错误）：蓝牙线程是原生线程，它用系统 class loader 去找类，而那个 loader
  看不到应用自己的类。现在启动时会把 Activity 的 class loader 交给这个线程。

## [0.4.0] – 2026-11-05

### 新增
- **训练回顾**（`回顾` 按钮；手机上在 `路线` 窗口底部）：全屏页面，可以比较一条路线上保存的训练（最多
  四个）。以距离为横轴的图表：功率、心率、踏频、速度和相对第一次训练的时差，共用一个游标。在剖面或
  图表上拖动，或者用爬坡按钮放大到某个路段：地图会高亮并显示这段路，图表和路段表格（时间、速度、
  平均与 NP 瓦数、心率、踏频、爬升、VAM、时差）也一起收窄到同一段。训练可以删除。
- **训练导入**：其他应用（Strava、Garmin、Wahoo）的 **GPX** 或 **TCX** 文件，带心率、踏频和瓦数。
  轨迹会投影到路线上（30 m 以内的点，绕出去的部分略去，自动暂停不计入时间），这样这次训练和其他训练
  共用同一条距离轴。文件是手动给定的（浏览或拖放），什么都不会离开这台机器。导入的训练不会成为 PR，
  也不会成为幽灵。
- **估算瓦数**：如果文件里没有功率，就把模拟的物理反过来跑（对 9 秒的窗口做能量平衡；坡度由路线
  给出）。计算用你自己的数据或自定义数值（体重、自行车、滚动阻力；CdA、传动效率和空气密度来自设置），
  结果带 `~` 标记，并且可以重新计算。实测瓦数永远不会被覆盖。
- 新的四色数据调色板，用于数据序列（`--series-1…4`，两个主题里都检查过）。
- **功率页面**（回顾里的 *比较 | 功率* 切换）：从你所有训练里取 5 秒、1、5、20 和 60 分钟的最佳平均
  瓦数；FTP 建议（最好 20 分钟的 95%）可以用一个按钮设置；负荷（TSS 和时间）按最近 12 周或 12 个月
  统计。只算实测瓦数：模拟的和估算瓦数的训练排除在外。旧训练的数字在第一次打开时算出来（`RideMeta.tss`、
  `RideMeta.mmp`），*20 分钟 FTP 测试* 的说明会引用它。
- **备份**（*设置 → 备份*）：一个 zip，包含路线、保存的骑行、导入的训练和设置。恢复只做合并，不删除
  任何东西，也不覆盖已有的骑行。Street View 密钥、瓦片、图片和日志不在里面；恢复时密钥也不会从文件里
  来。损坏的、过大的或文件名可疑的文件会被应用事先拒绝，什么都不会写。Android 上由系统的文件选择器
  （Storage Access Framework）处理；手机上还没试过。
- **Android 上骑行时屏幕保持常亮**（`FLAG_KEEP_SCREEN_ON`）。暂停时和骑行结束后，系统自己的息屏规则
  重新生效。手机上还没试过。

### 修复
- 手机顶部栏的“全屏”按钮没有按预期消失：匹配带重音符号的 `aria-label` 的 CSS 没找到它。改成了不带
  重音符号的类名。

### 面向开发者
- 新 crate：`ride-ui-review`。新模块：`ride-sim::{analysis, estimate, compare, power_curve}`、
  `ride-route::{activity, matching, import, backup}`。
- 新依赖：`zip` 4.6（MIT），只启用 `deflate-flate2-zlib-rs` 特性，`flate2` 早就在依赖树里。
- `RideRecord` 和 `RideMeta` 以增量方式扩展（`source`、`power_estimated`、`estimate`、平均值、
  路线名）；旧文件照原样加载。
- `RIDE_REVIEW=1` hook；`cargo run -p ride-route --example seed_review -- <目录> [路线.gpx]` 会把
  示例训练写进一个数据文件夹；`readme_shots.mjs` 新增 `review` 和 `review-phone` 场景。

### 移除
- **Strava 上传**：桌面端隐藏 WebView 的上传、Android 分享、“上传到 Strava” 按钮、Strava 栏，以及
  总结里询问 Strava 数据的表单（标题、描述、运动类型、备注、可见性）。原因：每次骑行后都要重新登录，
  这个功能因此没法用。TCX 保存保留（`保存为 TCX`，以前是“只保存为 TCX”）：文件可以手动上传到
  Strava、Intervals.icu 或 TrainingPeaks。
- 已经生成的 `strava` 和 `strava-webview` 文件夹在数据文件夹里从此变得多余；程序不会删除它们，可以
  手动删除（`strava-webview` 里是 Strava 登录用的配置文件）。

## [0.3.0] – 2026-11-03

### Android
- **系统文件选择器**（Storage Access Framework）：GPX 可以从手机上的任何位置加载；选中的文档由程序
  复制到应用的缓存里。
- **Android 上的蓝牙**：程序会初始化 `btleplug` 的 Android 后端，并申请运行时蓝牙权限；中枢不再因
  “Droidplug has not been initialized” 错误而挂掉，没有适配器时模拟骑手也仍然在。
  *（还没用真实设备试过。）*
- **连锁反应的根源已消除：** TLS 验证器（`rustls-platform-verifier`）在 Android 上会在事件循环里
  panic，而 `dioxus-desktop` 把所有事件都放在同一个全局锁下执行，于是第一次网络调用（启动五秒后的
  更新检查）之后，每次点击、窗口和标签页都跟着崩掉。Android 上程序现在用内嵌的 Mozilla 根证书做
  校验。
- **崩溃报告：** 捕获到的 panic 会写进 `files/crash.log`、进入 logcat，并显示为一行红色条带；处理
  函数不会让 panic 逃出去，应用仍然可用。
- `configChanges` 列出了所有配置变更（主题、字号、语言、密度），所以这些不会重建 `NativeActivity`
  （进程挺不过去）。`adjustResize` 和“点击输入框外部”的脚本：键盘不会遮住窗口。
- **自定义图标和启动画面**（`dx` 每次打包都会写进它自己的模板）。

### 界面
- 手机上顶部栏高 52 px，图标按钮 46 px（一个手指的大小）。
- 窗口：手机上页脚是两列网格；到处都去掉了多余的底部 *关闭* 按钮（每个窗口都有 ×，而且立刻保存）。
- “找到的设备”：操作按钮移到单独一行，不再遮住设备。
- 地图在跟随骑行者时，会在街道级别放大到骑行者，而不是整条路线。

## [0.1.1] – 2026-11-01

### 修复
- **控制那些从不确认控制权的 FTMS 骑行台**（见过的例子：VE200）：三次没有回应的 *Request Control*
  之后，程序假定拿到了控制权，并在没有确认的情况下发送命令；被拒绝的 *Start*、坡度和 ERG 写入
  （ATT `0x11`）会在写入间隔之后重试，而不是等到下一次 keep-alive。明确的拒绝仍然是拒绝。
- **BLE 十六进制日志始终会写**（`ble.log`）。
- Windows exe 在 CI 里静态链接 C 运行库，所以旁边不需要 DLL。
