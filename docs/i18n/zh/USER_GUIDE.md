## 首次启动

启动时，**路线**窗口会在空白的骑行屏幕上方打开。起步有三条路：GPX 文件、bikerouter 链接或演示路线。没有
硬件也能用**模拟骑手**骑完全程（见[连接设备](#连接设备)）。

![路线窗口](../../screenshots/route-dialog.png)

## 加载路线

- **GPX 文件。** 用文件对话框（`打开 GPX`、`Ctrl+O`）或把文件拖到窗口上。任何 GPX 都行：程序使用
  `<trk>`/`<trkseg>` 点（多个分段会依次接起来），没有的话用 `<rte>` 点；带重音符号、BOM 和命名空间的文件也
  读得懂；文件损坏（被截断）时给出看得懂的报错，而不是一条被截短的路线。大小上限是 64 MB。
- **Bikerouter 链接。** 在 [bikerouter.de](https://bikerouter.de) 上规划路线，点*分享*链接，把它粘到输入框里
  （`粘贴`，然后 `加载路线`）。点、配置文件、替代方案和避让都会从链接里带过来；路线由 BRouter 的服务器计算。
  原始的 BRouter 地址和 `lonlats=…` 参数也行。
- **演示路线。** 一段短的布达佩斯丘陵环线，用来先试试（坐标跑在道路*附近*，不在道路正上方）。
- **最近的路线。** 最近 20 条，带数据（距离、爬升、你打开它的时间、来源）；垃圾桶把它从列表里删掉
  （骑行日志保留）。

如果 GPX 里没有（可用的）海拔数据，程序会向 Open-Meteo 服务请求（坐标会发出去）；如果这也失败，路线就以平坦
剖面载入，并给出警告。从文件里：

- 如果主轨迹旁边有一条*更短的*轨迹落在路线上（比如塞进去的 Strava 赛段），或者有一条标了
  `<type>segment</type>` 的轨迹，它就会成为**赛段**：在剖面上显示为一条带，骑行中会有“赛段：… 还剩 X km”
  的提示（Strava 自己导出的 GPX 不含赛段）；
- 如果*每个*点都有时间戳（Strava 或 Garmin 导出），这条路线**同时也是它自己的幽灵**：见
  [幽灵与赛段](#幽灵与赛段)一节。

程序会在路线里找**爬坡**：长度至少 500 m、平均坡度至少 3%、爬升至少 25 m 的路段，等级从 4 级到 HC 级
（按长度 × 平均坡度区分）。

## 连接设备

顶部栏的**设备**按钮（旁边的三个点显示已经连上了几个角色）。有五个角色：**骑行台**（智能骑行台，FTMS）、
**心率**、**功率计**（CPS）、**踏频传感器**（CSC）和**变速器**（Zwift Click/Play）。

![设备窗口](../../screenshots/devices.png)

1. `开始扫描`：程序不筛选地扫描，并按设备广播的服务给它们分类（扫描 30 秒后自己停下）。
2. 找到的设备旁边是各角色的按钮：需要在哪个角色里用，就在哪个上面连。一个物理设备**可以同时承担多个角色**：
   如果你的骑行台也广播功率、踏频或心率，一次连接就能填满所有卡片（卡片上会显示*共用设备*标记）。传感器
   数据里更准的那个来源胜出（功率：功率计优先于骑行台；踏频：CSC，然后功率计，然后骑行台；心率：胸带优先
   于骑行台）。
3. 3 秒没更新的值会变成“—”；连接断掉时程序会重试三次。
4. **要把骑行台连在“骑行台”角色里**：功率计角色只读取，控制（爬坡、ERG）来自“骑行台”角色。
5. **模拟骑手**：列表第一项，永远都在，没有蓝牙也能用。在左侧面板用滑块（或 `↑`/`↓`，±10 W）设定瓦数，
   快捷按钮：Z2 150 W、Z4 250 W、冲刺 700 W、自由骑 0 W。踏频和心率会跟着它合理地变化。

**它怎么控制骑行台？** 爬坡时，骑行台拿到的是你前方路段的坡度（大约前方 5–45 m，做过平滑，最多 ±20%，
再按*坡度强度*设置缩放到 0–150%）。暂停时和结束时，骑行台回到平坦、中性的阻力。训练（ERG）时它保持目标
瓦数。发给骑行台的命令都要经过一道*安全过滤器*：只发必要的操作，目标值会被裁到骑行台自己的范围内。

> **重要，说实话。** ERG 控制我们用真实骑行台（VE200）试过；爬坡模拟还没有用真实骑行台确认过，Zwift
> Click/Play 控制器、单独的心率带和功率计也还没有用真实硬件试过。细节见 [`TESTING.md`](../../TESTING.md)。

## 骑行

按 `开始`（或 `Space`）就出发，`暂停`停下（时间也停），`结束`收尾。到路线终点时，骑行**会自己结束**。
开始之前，点一下剖面就能跳到路线上任意一点；骑行中不行。骑行时程序会让电脑保持唤醒（Windows、Linux、
macOS；Android 上不会）。

速度来自测得的**瓦数**，用的是经过道路实测验证的 Martin 模型（重力、滚动阻力、轴承摩擦、含辐条的风阻、
惯性），输入是你的体重、车重、CdA 和 Crr；打开*使用骑行台的速度*开关，也可以采用骑行台自己的速度。细节见
[`SIMULATION.md`](../../SIMULATION.md)。

![骑行，深色主题](../../screenshots/ride-dark.png)

## 屏幕与布局

骑行屏幕由**面板**组成：*地图*、*功率*（大号数字、3 秒平均、W/kg、区间）、*下一段爬坡*、*统计*、*海拔剖面*、
*控制*、*图表*、*训练*、*模拟骑手*、*档位*、*浏览器*。它们像平铺窗口管理器里那样工作：
**不重叠，也不留空。**

- **缩放：** 拖分隔线（那条线会吸附到 96 × 64 网格的格子上，并遵守面板的最小尺寸；只有相邻的两个面板会变）。
- **移动：** 抓住面板标题栏，丢到另一个面板的*边缘*上会把它一分为二，丢到*中间*则两者交换位置（有半透明框
  提示结果）。
- **关闭：** 面板的 × 按钮；相邻面板补上它的位置，面板变成一个*标签块*进到顶部栏。点标签块，它回到原来的
  位置；把它拖到界面上，就放在你松手的地方。
- **一切都会保存。** *设置 → 布局 → 重置布局*恢复默认。
- 布局（以及剖面的视图）程序**对有训练和无训练分别记录**：选中的训练有自己的布局，在你没在训练里改过之前，
  它跟着无训练的那套走。

![浅色主题](../../screenshots/ride-light.png)

**地图。** 地图显示标准的 OpenStreetMap 瓦片；*深色*和*浅色*样式在本地给它们做滤镜，*OSM* 是原图。滚轮以
鼠标为中心缩放，拖动平移；左下角的按钮打开跟随模式并居中（`M`）。路线颜色表示坡度（冷色：下坡，灰色：
平路，黄–橙–红–紫：越来越陡的爬坡），骑手是带箭头的圆盘。底部是 OSM 署名和比例尺。

**海拔剖面。** `全程`（整条路线）或 `前瞻`（接下来约 3 km；长度可以在设置里调，`P`）；爬坡以旗标显示并带
等级，下面是公里刻度；点击可以跳转（骑行前），鼠标悬停可以读数。前瞻的比例尺只在必须时才切换。如果有选中
的训练，**海拔 | 训练**开关会显示训练的区块。

**文字大小。** *设置 → 外观 → 文字大小*（80–160%）。

**语言。** *设置 → 外观 → 语言*：*自动*（跟随系统语言，前提是它的文本完整）、*Magyar*（匈牙利语）、
*English*（英语）、*Español*（西班牙语）、*Português*（葡萄牙语）、*Deutsch*（德语）、*Italiano*（意大利语）、
*简体中文*（中文）。切换立刻生效；它不会重命名你早先起的路线名和骑行名（那些保持你
起的名字）。

## 训练

顶部栏的**训练**按钮（或 `W`）。内置库有 **93 个训练**，分 12 个类别（恢复、耐力、节奏、甜区、阈值、VO2max、
无氧、冲刺、爬坡、比赛、测试、混合），其中有 20 分钟和 8 分钟的 FTP 测试、ramp 测试和 CP 测试，还有很多
遵循已发表研究方案的训练课（Rønnestad 30/15、Seiler 4 × 8、Helgerud 4 × 4、Billat 30/30、Gibala 冲刺间歇等等；
出处按训练列在 `workouts.json` 的 `sources` 字段里）。

![训练选择器](../../screenshots/workout-picker.png)

- 左边是类别和**标签**（适合什么、水平、性质、周期；它们按“与”的关系筛选，旁边是命中数量），中间是列表，
  右边是说明（做什么、为什么、怎么做）、**按区间着色的区块图**，以及逐个区块的列表：时间、目标、教练指示。
- 目标按 **%FTP** 算：在*设置 → 骑行者*里填 FTP；改动之后，剩下的部分立刻重新计算。
- 骑行中骑行台以 **ERG 模式**保持目标瓦数，*训练*卡片和剖面面板的*训练*视图显示当前区块、剩余时间、下一个
  区块，以及**教练提示**（在训练合适的那一刻出现，持续 12 秒，只在那个位置，不弹窗）。这里暂停/退出同样会
  让骑行台回到中性阻力。
- **自己的训练：** *导入训练…* 能读 MyWhoosh 或 Zwift 的文件（`.xml`、`.zwo`），也能读 MyWhoosh 的 JSON
  导出；它会被放进 `workouts/` 文件夹，之后就能像其他训练一样选了。
- 骑行中不能换训练。

![训练在 ERG 模式下](../../screenshots/workout.png)

## 虚拟变速

*设置 → 骑行台 → 虚拟变速。* 2 × 12 传动（50/34 和 11–34），**23 个档位**。用 `←`/`→` 键、档位面板、手机上
的变速按钮或 Zwift Click/Play 控制器换档。因为智能骑行台没有变速箱，档位改变的是发给骑行台的坡度（最轻档
大约 −5%，最重档大约 +5%）；面板显示该档的齿比和由踏频算出的速度。
**训练（ERG）期间变速不显示、也不起作用**（目标瓦数说了算）。用 Zwift Click/Play 控制器时，第一次换档就
会打开变速；Click 的 `+` 往更重档走，
`−` 往更轻档走，Play 右手控制器是 `Shift`/`Y`，左手控制器是 `Shift`/`B`（这一条还没有用真实控制器试过）。

## 幽灵与赛段

每个完成的骑行都会**自动保存**到路线上（逐秒记录、总结、赛段用时），在同一条路线上，之前的骑行可以当作
**幽灵**回放：开始前它就在起跑线上等，骑行中地图和剖面上的半透明标记显示它当时走到了哪里；领先/落后以秒
显示。*设置 → 地图与剖面 → 幽灵*：

| 模式 | 回放什么 |
|---|---|
| 关 | 什么都不回放 |
| 路线时间 | 载入的 GPX 自带的时间戳（Strava/Garmin 导出的话，第一次骑行之前就能比赛；BRouter 路线里没有时间） |
| 上次骑行 | 这条路线最近的那次骑行 |
| 最佳（PR） | 用时最短的**完整**骑行；如果还没有一次骑到终点，就是走得最远的那次（部分）骑行，它会在自己的终点停下 |

选择器下面那一行会告诉你为什么现在没有幽灵。识别出的爬坡是**本地赛段**：开始前显示最好成绩（PR），骑在
里面时显示精确到秒的差值，总结里有“之前的 PR”和“新 PR！”徽章。用**模拟骑手**骑的那次会保存，但不会成为
PR，也不会成为“最佳”幽灵。

## 总结与 TCX

到路线终点（或按过 `结束`）之后会打开**总结**：距离、时间、爬升、平均功率和标准化功率、IF、TSS、能量、
平均速度、心率、赛段表和功率/心率区间的分布。

![总结](../../screenshots/summary.png)

底部是 `保存为 TCX` 按钮（Garmin 的格式；建议的文件名由日期和路线名组成）和 `新路线`。

**上传到 Strava、Intervals.icu、TrainingPeaks：** 没有内置上传。在 Strava 自己的网站上，用*上传文件*菜单
可以手动传保存好的 TCX；Intervals.icu 和 TrainingPeaks 也接受。0.3.1 之前有一个后台上传器，但在我们这儿
每次骑行之后都得重新登录，所以去掉了（0.3.2）。

## 回顾并对比骑行

**`回顾`** 按钮（顶部栏；手机上在 `路线` 窗口底部的*回顾已保存的骑行*）打开一个全屏页面。`Esc` 或 `返回`
关掉它；它下面骑行屏幕原样保留。

![回顾页面](../../screenshots/review.png)

**列表。** 左边是路线（选择器里是每一条有已保存骑行的路线，加上当前载入的）和它的骑行，最新的在前。最多选
四个：每个分到一个字母（A–D）和一种颜色，图表上的线型也不同（A 是实线）。**A 是参照骑行**：*时间差*图表
和表格的*差值*列都是相对它而言（正数 = 更慢）。垃圾桶删除前会先问。默认选中这条路线最近两次骑行。

**图表。** *功率*、*心率*、*踏频*、*速度*或*时间差*，横轴是距离。把鼠标（或手指）在剖面或图表上移动时，
图例里能读到光标处各次骑行的数值，地图上有一个点标出位置。如果某次骑行没有这种传感器（比如没戴心率带），
它就没有那条线。

**放大到某一段。** 在剖面或图表上按住鼠标拖过去（触摸屏上用手指），或者点*爬坡*按钮；`全程路线`恢复原状。
地图会放大并高亮这一段，图表和表格也收窄到同一段。短于 100 m 的拖动不算一段。

**路段表格。** 每次骑行一行：时间、平均速度、平均功率和标准化功率（NP，至少 30 秒数据）、平均和最大心率、
踏频、爬升、VAM，以及与参照骑行的差值。只有骑行**完整骑完**的路段才有数据；部分骑行在其他路段上是空的。

### 功率：峰值、FTP、负荷

![功率页面](../../screenshots/review-power.png)

回顾页顶部有**对比 | 功率**开关，可以去另一页。这里是你**所有**骑行的数字，与路线无关：

- **峰值功率。** 5 秒、1、5、20 和 60 分钟的最好平均瓦数，带骑行日期和路线。如果你在对比页里选了骑行，
  它们的值按列排在旁边（A–D）。比这次骑行更长的时间段没有值。
- **FTP。** 它会把最好 20 分钟功率的 95% 作为 FTP 建议，旁边显示当前设置的值。**将 FTP 设为 N W** 按钮会把它
  写进设置；程序自己从来不改它。已保存骑行的 TSS 仍按它们当时的 FTP 计算。要有准确的建议，需要一次真正的
  20 分钟全力骑行：*FTP 测试 20 分钟*训练（*训练*，`W`）正好给这个。
- **负荷。** 最近 12 周或 12 个月（*每周* | *每月*）：柱子显示 TSS，上面是数值，提示（停在柱子上）显示
  骑行次数和时间。

**只有实测瓦数才算数。** 模拟骑手和带估算（`~`）瓦数的骑行不会进入峰值和 FTP 建议（在趋势的时间部分会，
在它的 TSS 里不会）。导入的骑行如果里面是真实功率，就算。骑行台自己的瓦数不是功率计，所以 FTP 建议也只能
准到那个程度。旧骑行的数字在第一次打开时算好并保存，骑行很多时要花几秒钟。

### 从其他应用导入骑行

**`导入骑行`** 按钮（或者把文件拖到页面上）载入一个 GPX 或 TCX 文件，比如从 Strava、Garmin 或 Wahoo
导出的。心率、踏频和（如果有）瓦数会带过来。要知道的：

- **路线由你指定**：骑行会被贴到页面上选中的那条路线（先载入或选中它）。轨迹的点会投影到路线上；离路线
  超过 30 m 的（绕路、GPS 误差）会被丢掉，丢掉多少页面会写出来。如果骑行只覆盖路线的一部分，它会警告。
- **自动暂停**（长时间停止）不计入时间。没有时间戳的文件（比如一条规划好的路线）不能作为骑行导入。
- 同一次骑行（同一个开始时间）不能导入两次。
- 导入的骑行**不会成为 PR，也不会成为幽灵**：外面的一次骑行有停顿、有滑行，和你在骑行台上的时间没法比。
  列表里用 `已导入` 标签标出。
- 手机上还不能导入。我们不读 FIT 格式；Strava 会导出 GPX 和 TCX。

### 估算功率

如果文件里**没有功率数据**，程序会把模拟的物理反着跑一遍：由速度和坡度算出当时需要多少瓦（9 秒窗口里动能
的变化，以及对抗重力、滚动、轴承和空气做的功）。这样的骑行上，数字带 **`~`** 号，并显示 `估算功率` 标签。

用滑块图标（*估算设置*）可以指定按谁的数据算：

| 选择 | 用什么 |
|---|---|
| **我的数据** | 设置里的体重、自行车和 Crr |
| **自定义数值** | 这里填的*体重*、*自行车*和*滚动阻力（Crr）*，用来看别人的骑行 |

CdA、传动效率和空气密度一律取自设置。好沥青上的 Crr 大约是 0.004；**碎石路没有单独的模型**，那里只有你
填的 Crr 在起作用。`重新计算`用新值重算并保存这次骑行；程序永远不会用估算覆盖实测瓦数。

**准不准？** 是近似值。它不知道风，也不知道跟车（逆风看起来瓦数更少），坡度来自路线，而不是文件里带噪声的
GPS 高度，急弯处投影可能短时间给出有噪声的速度。用程序自己的物理反算，能把整段骑行还原到大约 3% 以内；我们
还没有和真实功率计比过，所以要按 10–15% 的偏差来估。

## Street View（可选）

Google 只通过它的 API 提供这个，所以需要**你自己的 Google Maps API 密钥**（*设置 → Street View*；步骤
那里写着：Google Cloud 项目、结算、启用 *Maps Embed API* 和 *Street View Static API*）。没有密钥就什么都
不显示。按 `V` 或地图面板上的 `Street View` 按钮，会把它以小窗口放到地图右下角；`X`（或交换按钮）把两个
视图对调。出错时给出看得懂的提示（密钥无效、配额用完、这个地方没有全景）。**下载**按钮给路线每 75–250 米
存一张图（最多约 900 张；30 天内有效，可以在设置里删掉），这样下次没有密钥、没有网络也能骑完同一条路。
下载用的是你自己的 Google 配额。细节和 Google 的规则：[`STREETVIEW.md`](../../STREETVIEW.md)。

### 备份

*保存到文件*把你的路线、保存的骑行、导入的训练和设置打成一个 **zip 文件**。文件由你选（Android 上用系统
的“另存为”对话框），没有任何东西发到网络。**里面不包含** Street View 密钥、地图瓦片、下载的 Street View
图片和日志：这些要么是机密，要么随时可以重新下载。

*从文件恢复*是**合并**：备份里的路线、骑行和训练加进现有的里面，
**什么都不会被删掉，已有的骑行也不会被覆盖**。但备份里的设置会生效（你的 Street View 密钥还是旧的），
所以应用会先问。同一个文件恢复两次不会有任何变化。换到新机器时，恢复这个文件就行。骑行中不能做备份，
也不能恢复；如果文件损坏或来自更新的版本，应用会说明，并且什么都不写。Android 上这部分还没在手机上试过。

## 浏览器面板（仅 Windows）

**浏览器**面板把装在机器上的 **Firefox** 嵌进窗口，骑行时可以看剧或看别的。Firefox 用自己的配置文件（你的
登录保留，不会动你平时的 Firefox）。Mac 和 Linux 上这个面板不出现。打开窗口或拖动面板时 Firefox 会临时藏
起来（界面没法画在原生窗口之上）；关闭面板也会关掉 Firefox；宽度最好至少约 500 px。

## 故障排查

| 症状 | 怎么办 |
|---|---|
| 骑行台对爬坡 / 训练没反应 | 在**设备**窗口里要用*骑行台*角色连接（功率计角色只读取）。看看 BLE 日志（`ble.log`，按 [`BLUETOOTH.md`](../../BLUETOOTH.md) §11 的方法）；别让 Zwift 或手机应用占着骑行台。 |
| 找不到设备 | 打开蓝牙；Windows 上扫描不筛选，所以能看到很多设备：看设备的角色。Android 上授予蓝牙权限（*开始扫描*会再问一次）；macOS 上系统会在第一次扫描时请求权限。 |
| 地图空白或灰色 | 没有网络，也还没有缓存的瓦片：路线和数字照常工作。 |
| 路线载入不了 | 报错会说原因（文件损坏、链接不支持、连不上 BRouter）。链接里必须包含 `lonlats=` 部分。 |
| 剖面是平的 | 文件里没有海拔数据，Open-Meteo 也连不上。载入带海拔的 GPX 或 bikerouter 链接。 |
| Linux 上窗口空白 | 程序会自己设置 `WEBKIT_DISABLE_DMABUF_RENDERER=1` 变量；如果还是空白，试试 `WEBKIT_DISABLE_COMPOSITING_MODE=1`。 |
| macOS：“无法打开” | 右键 → 打开 → 打开（应用没有经过公证）；或者 `xattr -dr com.apple.quarantine /Applications/bike-osm-ride.app`。 |
| Windows：SmartScreen 警告 | 程序没有数字签名，所以 Windows 可能拦下它；走*更多信息 → 仍要运行*就能启动。 |
| 崩溃 / 红条 | 第一行在红条里，完整日志在 `crash.log`（Android 上是 `adb logcat -s bike-osm-ride`）。请把日志一起报上来。 |

**我的数据在哪？** 在一个文件夹里，和设置、骑行日志、瓦片、日志放在一起（想要副本就用*设置 → 备份*
按钮）：Windows `%LOCALAPPDATA%\bike-osm-ride`，macOS `~/Library/Application Support/bike-osm-ride`，
Linux `~/.local/share/bike-osm-ride`，Android 是应用的私有文件夹。具体结构见
[`ROUTES_AND_DATA.md`](../../ROUTES_AND_DATA.md)；什么会离开这台机器，见 [`PRIVACY.md`](PRIVACY.md)。
